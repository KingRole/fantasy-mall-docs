﻿


**2. FmInput number 类型输入规则**

﻿


目前 type='number'、modelValue 为字符串，但文档称禁止浮点。字符串存储本身不能阻止小数输入。

﻿


请明确：

- 如果本组件只允许整数，定义整数输入限制、非法输入处理、空值及边界值规则。

- 如果允许小数，则删除禁止浮点的说法，并明确数值精度与数据处理边界。

- 不能只依赖原生 input type=number 就声称实现了整数限制。

- 不要把金额计算或复杂数值格式化功能提前放入 FmInput。

﻿


同步 Props、Events、数据契约和验收标准。

﻿


**3. FmSelect 空值契约**

﻿


当前 modelValue 为 string | number，但 update:modelValue 又允许 null。

﻿


请统一：

- 明确无选中值和清除后的空值表示。

- 如果使用 null，modelValue 类型必须同步包含 null。

- 明确默认值。

- 明确清除操作是否同时触发 change，以及事件 payload。

- 保证 Props、Events、摘要和验收一致。

﻿


**4. FmDrawer 无标题时的 accessible name**

﻿


当前无 titleKey 时允许 aria-labelledby 指向关闭按钮或正文首标题，不能保证所有场景都有准确、可理解的 dialog 名称。

﻿


请明确无标题情况下的处理：

- 提供可访问名称的 aria-label 契约，或

- 要求正文必须提供可关联标题。

不能把关闭按钮的“关闭”作为默认对话框名称。

同步 Props、交互与可访问性、验收标准。

居中模态对话框：承载需要用户短暂专注的浮层内容（表单、详情、提示）。浮层机制（遮罩 / z-index / 焦点陷阱 / Esc / reduced-motion）的唯一定义处，被 FmConfirm(8)、FmDrawer(9) 继承（U-1）。不负责：轻量反馈（→ FmToast）、二次确认文案组合（→ FmConfirm）、手机底部抽屉形态（→ FmDrawer）。

居中模态，宽高自适应内容；底 --fm-modal-bg、阴影 --fm-modal-shadow、圆角 --fm-modal-radius、内边距 --fm-modal-pad-pc；标题 --fm-modal-title-size / --fm-modal-title-color、正文 --fm-modal-body-color；层级 --fm-modal-z，遮罩 --fm-modal-mask-z（遮罩色见 §5 TBD-05）；容器 1200 / 1440 内居中，不写死宽。

独立布局非缩放；内边距 --fm-modal-pad-mobile；375 / 390 / 430 宽度自适应（左右留白），不溢出；弹层避开 iOS 安全区；触控关闭按钮 ≥44×44；modal 形态在手机仍为居中（底部抽屉用 FmDrawer）。


5

组件职责与边界
	
重要操作的二次确认对话框（删除、清空、不可逆提交等）。基于 FmModal 浮层机制，只增确认 / 取消按钮组合与二次确认文案（U-1）。不负责：普通信息展示模态（→ FmModal）、表单录入（→ FmModal + 表单组件）。


2
	
Props / Events / Slots
	
完整契约见 §4.2.1。摘要 —— Props：modelValue（boolean，必填）、titleKey（必填）、messageKey（必填，确认正文 key）、tone（'danger' / 'warning' / 'default'，默认 'default'）、confirmKey（默认 fm.confirm.ok）、cancelKey（默认 fm.confirm.cancel）、loading（默认 false）、disabled（默认 false）；Events：update:modelValue、confirm、cancel；Slots：无（文案全经 key）。


3
	
PC 变体
	
复用 FmModal 居中形态与 --fm-modal-*（#71～#82）；语义图标色：tone='danger' → --fm-confirm-icon-danger，'warning' → --fm-confirm-icon-warning，'default' 无图标；确认 / 取消按钮用 FmButton 基座，危险确认用 --fm-btn-bg-danger。


4
	
手机变体
	
继承 FmModal 手机行为（居中、宽度自适应、触控 ≥44×44、安全区）；按钮双端通栏或并排按内容自适应；375 / 390 / 430 不溢出。


5
	
状态矩阵
	
同 FmModal 开合状态（继承）；确认按钮 default / hover / focus-visible / disabled / loading：disabled=true 或 loading=true 时确认不可点击（防重复提交）、可辨识且不可聚焦；取消按钮始终可用（除非 closable 语义禁用）。


6
	
交互与可访问性
	
完全继承 FmModal 的焦点陷阱 / 初始焦点 / Esc / 关闭返回（引用 M-01～M-03，不重复定义浮层机制）；确认按钮默认获得初始焦点（危险操作默认落在「取消」更安全，规范卡定 tone='danger' 时初始焦点落取消按钮，防误触）；确认 / 取消按钮文字按 1.4.3 普通文本 4.5:1；tone 图标为装饰，不作为唯一语义线索（语义由文案承载）；aria-describedby 关联正文（对应 §2.1 弹窗行）。


7
	
Token 依赖
	
复用 --fm-modal-*（#71～#82）+ 本批 #83～#84 图标语义色 + FmButton 基座 --fm-btn-*（《34》#1～#27）；危险按钮色 --fm-btn-bg-danger / --fm-btn-text-on-danger。


8
	
i18n
	
titleKey / messageKey / confirmKey / cancelKey 全为 key，组件内 t()；内置默认 key fm.confirm.ok / fm.confirm.cancel；缺失回退 zh-CN；无写死文案；确认文案含变量名时用 I18nText 插值，不拼接翻译。


9
	
数据契约
	
无业务数据字段；确认结果经事件传出、不访问 Dexie；messageKey 所指文案可含动态数据（由调用方经插值参数提供）。


10
	
验收标准
	
CF-01 继承浮层机制且引用 M-01～M-06（不重复实测）；CF-02 tone 三档图标色正确；CF-03 危险确认初始焦点落「取消」防误触；CF-04 confirm / cancel 事件参数正确、loading/disabled 防重复提交；CF-05 aria-describedby 关联正文；CF-06 双端与文案 i18n 齐备。对应全局：《30》§5.4 a11y 矩阵「弹窗」行 / i18n。


11
	
复用关系
	
基座 = FmModal（U-1 / U-4）：继承遮罩 / z-index / 焦点陷阱 / Esc / reduced-motion（M-01～M-06），自身差异仅「确认 / 取消按钮组合 + tone 图标 + 二次确认文案 + 危险态初始焦点策略」；Layer 3 别名仅 #83～#84 差异色。

4.3 FmDrawer（C-05 · 序号 9）
#
	
字段
	
内容


1
	
组件职责与边界
	
抽屉式浮层：手机底部抽屉（筛选、详情、操作面板）与 PC 侧滑抽屉。基于 FmModal 浮层机制，只增形态（底部 / 侧滑）、尺寸与滑入动效差异（U-1）。不负责：二次确认（→ FmConfirm）、居中模态（→ FmModal）。


2
	
Props / Events / Slots
	
完整契约见 §4.3.1。摘要 —— Props：modelValue（boolean，必填）、placement（'bottom' / 'left' / 'right'，默认 'bottom'）、titleKey（string，可选）、dialogLabelKey（string，可选，无标题时必填，作 aria-label 可访问名称兜底）、closable（默认 true）、closeOnMask（默认 true）、closeOnEsc（默认 true）；Events：update:modelValue、open、close(reason)；Slots：默认（正文，必需）、title、footer。可访问名称硬约束：有标题 → aria-labelledby 指向标题；无标题 → 必须由 dialogLabelKey 提供 aria-label；二者皆缺视为实现错误，严禁用关闭按钮「关闭」文案作 dialog 名称。


3
	
PC 变体
	
侧滑抽屉（placement='left'/'right'），底 --fm-modal-bg、阴影 --fm-modal-shadow、层级复用 --fm-modal-z；内边距 --fm-modal-pad-pc；宽度随内容自适应、不写死。


4
	
手机变体
	
主形态为底部抽屉（placement='bottom'）：顶部圆角 --fm-drawer-radius-top、内边距 --fm-drawer-pad、底部安全区 --fm-drawer-safe-bottom；滑入时长 --fm-drawer-duration；触控拖柄 / 关闭按钮 ≥44×44；375 / 390 / 430 通栏不溢出。


5
	
状态矩阵
	
开 / 关 / entering / leaving（继承 FmModal）；关闭按钮 hover / focus-visible；reduced-motion 下滑入趋零、不保留持续动画（引用 M-06，不重复定义）。


6
	
交互与可访问性
	
复用 FmModal 焦点陷阱 / 初始焦点 / Esc / 关闭返回（引用 M-01～M-03）；role=dialog + aria-modal=true；可访问名称二选一（必须成立其一）：① 有 titleKey / title 插槽 → aria-labelledby 指向标题元素；② 无标题 → dialogLabelKey 提供 aria-label（组件内 t(dialogLabelKey)，如「筛选条件」「商品详情」）。若二者皆缺，视为实现错误（开发态告警），不得渲染出无名称 dialog；严禁用关闭按钮 key fm.drawer.close（「关闭」）作 dialog 的 aria-label/aria-labelledby——关闭按钮自身的 aria-label 仍为 fm.drawer.close（对应 §2.1「图标-only aria-label」），二者用途不同、不得混用；焦点可见（2.4.7）；按钮文字 1.4.3 分层；遮罩色见 TBD-05。滑入为进出场过渡，不作为持续动画。


7
	
Token 依赖
	
复用 --fm-modal-z / --fm-modal-mask-z / --fm-modal-shadow / --fm-modal-bg / --fm-modal-focus-ring（#71～#74、#81）+ 本批 #85～#88 形态差异别名；按钮复用 --fm-btn-*。


8
	
i18n
	
titleKey / dialogLabelKey 由调用方传 key（后者供无标题时 aria-label）；内置 key fm.drawer.close（仅关闭按钮 aria-label，不得复用为 dialog 名称）；正文 / footer 经插槽由调用方 t()；无写死文案、无拼接翻译。


9
	
数据契约
	
无业务数据字段；开合经 v-model；筛选类抽屉的筛选条件由调用方持有、经事件回传；不访问 Dexie。


10
	
验收标准
	
D-01 继承浮层机制并引用 M-01～M-06；D-02 placement 三档形态正确、手机底部抽屉安全区生效；D-03 图标关闭按钮 aria-label 100% 存在（§2.1 图标行）；D-04 焦点陷阱与关闭返回有效；D-05 reduced-motion 无持续动画；D-06 双端 375/390/430 不溢出；D-07 可访问名称：有标题时 aria-labelledby 指向标题、无标题时 dialogLabelKey 生成 aria-label，二者皆缺时开发态告警且不渲染无名称 dialog；断言任何情况下 dialog 名称 ≠ 关闭按钮「关闭」文案。对应全局：《30》§5.4 a11y 矩阵「弹窗」行 / 双端 / i18n。


11
	
复用关系
	
基座 = FmModal（U-1 / U-4）：继承遮罩 / z-index / 焦点陷阱 / Esc / reduced-motion，自身差异仅「底部 / 侧滑形态 + 顶部圆角 + 滑入动效 + 安全区」；Layer 3 别名仅 #85～#88 差异项，不复制浮层机制。

4.4 FmFormField（C-06 · 序号 10）
#
	
字段
	
内容


1
	
组件职责与边界
	
字段容器：统一 label / 必填标记 / 控件槽 / 辅助说明 / 校验提示的关联与布局；字段容器与校验提示机制的唯一定义处（U-1），被 C-06 各输入控件复用。不负责：控件自身的输入交互（→ FmInput 等各控件卡）、表单整体提交（→ 调用方）。


2
	
Props / Events / Slots
	
完整契约见 §4.4.1。摘要 —— Props：labelKey（string，必填）、required（默认 false）、errorKey（string，可选）、hintKey（string，可选）、forId（string，必填，用于 label / 控件 / 提示关联）；Events：无（纯容器）；Slots：默认（控件，必需）、hint、error。


3
	
PC 变体
	
label 用 --fm-field-label-color / --fm-field-label-size；辅助说明 --fm-field-hint-color；错误提示 --fm-field-error-color（小字号红字收敛点 --color-text-safe-red）；各区间距 --fm-field-gap；必填标记在 label 后、语义由文字 / aria 承载而非仅颜色。


4
	
手机变体
	
同视觉规范；label 与提示不缩小到 <12px；375 / 390 / 430 标签与控件不重叠、错误提示换行不溢出；触控区由内部控件保证 ≥44×44。


5
	
状态矩阵
	
default / error / disabled（经内部控件传导）/ readonly；error 态显示校验提示并设 aria-invalid/aria-describedby；无 hover / focus（容器非交互件，焦点在内部控件）。


6
	
交互与可访问性
	
<label for=forId> 与控件 id 关联（持久可见 label，不依赖 placeholder）；错误提示经 aria-describedby 关联到控件，控件 aria-invalid=true；必填经 aria-required 或 label 文字（非仅颜色）；错误文字 --fm-field-error-color ≥4.5:1（1.4.3 普通文本）；提示 icon 若存在为装饰、不作唯一线索（对应 §2.1 FmInput 行 aria-invalid/aria-describedby）。


7
	
Token 依赖
	
本批 #89～#93；内部控件复用各自 --fm-input-* / --fm-checkbox-* 等；不新增色值。


8
	
i18n
	
labelKey / errorKey / hintKey 全为 key、组件内 t()；内置必填标记 key fm.field.required（供 aria / 视觉）；动态错误文案用 I18nText 插值，不拼接翻译。


9
	
数据契约
	
无业务数据字段；forId 由调用方保证同表单内唯一；校验结果由调用方经 errorKey 传入；不访问 Dexie。地址 mock 与真实模型同构（《30》§4.3 C-06）。


10
	
验收标准
	
FF-01 label / 控件 / 提示三者 for/id/aria-describedby 关联正确；FF-02 error 态 aria-invalid 同步且提示文字 ≥4.5:1；FF-03 必填语义非仅颜色；FF-04 错误文字用 --color-text-safe-red 收敛点；FF-05 双端标签与提示不重叠 / 不溢出；FF-06 全部文案走 key。对应全局：《30》§5.4 WCAG / a11y 矩阵「FmInput」行 / i18n。


11
	
复用关系
	
字段容器基座（定义处）。FmTextarea/FmSelect/FmCheckbox/FmRadio/FmSwitch/FmStepper 复用 label 关联 / 校验提示 / 错误态 aria-describedby（§1.2；U-1 / U-5）；FmInput 的 aria-invalid/aria-describedby 由本容器注入（§2.1）。

4.5 FmInput（C-06 · 序号 11）
#
	
字段
	
内容


1
	
组件职责与边界
	
单行文本输入框；输入框基础样式、空白 / 已填写 / 焦点三状态与无障碍规则的唯一定义处（U-1），被 FmTextarea / FmSelect / FmSearchInput 继承。不负责：多行（→ FmTextarea）、搜索语义 / 清除（→ FmSearchInput）、label 与校验提示布局（→ FmFormField）。


2
	
Props / Events / Slots
	
完整契约见 §4.5.1。摘要 —— Props：modelValue（string，v-model）、id（string，必填，与 FmFormField.forId 关联）、placeholderKey（string，可选）、type（'text' / 'password' / 'tel' / 'email' / 'number'，默认 'text'）、disabled（默认 false）、readonly（默认 false）、invalid（默认 false）、maxlength（number，可选）；Events：update:modelValue、focus、blur、enter；Slots：无（本批不支持 prefix / suffix 前后缀 Props，未定义相关契约；未来扩展须单独提交变更并重新验证三状态）。


3
	
PC 变体
	
高度 --fm-input-height-pc、圆角 --fm-input-radius、底 --fm-input-bg；已填值 --fm-input-text、占位 --fm-input-placeholder；边界 --fm-input-border（承担识别功能须独立 ≥3:1）；focus 边界 --fm-input-border-focus、宽 / 偏移 #100/#101；错误边界 --fm-input-error-border。


4
	
手机变体
	
高度 --fm-input-height-mobile（48px ≥44 触控达标）；字号 ≥16px 避免 iOS 聚焦缩放；375 / 390 / 430 输入区通栏自适应、不溢出；placeholder 不替代持久 label。


5
	
状态矩阵

8
	
i18n

9
	
数据契约
	
modelValue 恒为字符串（含 type='number'，允许小数），值以用户输入原样保存——这是为避免 JS number 二进制浮点精度丢失，不是「禁止浮点」语义。组件不做数值解析 / 取整 / 金额最小单位换算 / 千分位与精度格式化；整数化、金额最小货币单位整数运算（utils/money）与格式化属业务层职责，由 C-11 金额类组件 / 调用方 Service 承担（《30》C-11），不在本输入基座提前实现。空值统一为 ''；合法数值字符集与 max / min / 步长等约束由调用方按需校验并经 FmFormField 提示，本组件不替业务做数值合法性判定。不访问 Dexie；地址 / 表单字段与真实模型同构（mock 同构）。
